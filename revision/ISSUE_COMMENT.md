**Spanish (es) localization — heads-up before I open a PR**

Hello! I have been working on a Spanish localization and I would like to check
the direction with you before opening the pull request.

**What it covers**

- `locales/es.json` — the full interface, 149 messages, mirror of `en.json`.
- `app/i18n.tsx` — `LocaleProvider` + `useT()`, no new dependencies, English as
  the fallback for missing keys.
- EN/ES switch in the header, plus hover tooltips, panels, error messages, the
  model downloader and the accessibility strings in `components/ui`.
- `locales/anatomy.es.json` — **1,808 of the 2,234 structure names (81%)**,
  generated by `scripts/build-anatomy-es.py` from `public/models/atlas.json`
  with a Terminologia Anatomica glossary and Spanish agreement rules.
- Search now matches Spanish, English and the FMA ids.

**Two things I would like your call on**

1. **Structure names.** The remaining 19% are labels with sentence-like
   connectors (`Communicating branch of left nasociliary nerve with left
   ciliary...`). I left those in English on purpose rather than shipping broken
   Spanish. Would you prefer them attempted anyway, or reviewed by hand later?
2. **Coexistence with other locales.** I followed the same `locales/<lang>.json`
   structure as the Georgian, Uzbek, Hindi and Chinese work, so the catalogues
   stay independent. If you would rather have a single shared file per language
   (or per-name dictionaries as in #323), I can restructure before submitting.

**Verification:** `npm run check` clean, `npm run build` succeeds, and
`scripts/check-i18n.py` confirms both catalogues stay in sync (86 keys used, 149
messages each). No new dependencies and no changes to the 3D pipeline.

Happy to split it, rename keys or reshape anything you prefer. Thanks for the
atlas — it is a pleasure to work with.
